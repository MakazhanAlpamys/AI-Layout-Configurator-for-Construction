# Kazakhstan: «СН РК 3.02-02-2023» (English: SN RK 3.02-02-2023)

## Source decision

Kazakhstan was chosen for the first jurisdiction profile. The official PDF of the
Committee for Construction and Housing and Communal Services was used:

- document: **СН РК 3.02-02-2023 «Проектирование одноквартирных жилых домов и
  их инженерных систем»** (English: SN RK 3.02-02-2023 "Design of single-family
  residential houses and their engineering systems");
- verified edition: the official PDF printed in Astana in 2024;
  the foreword also notes editorial amendments dated 20.11.2024;
- official source: <https://new-shop.ksm.kz/media/egfntd/ntdgo/3_02_02_2023.pdf>;
- effective date stated in the document: 2023-06-16;
- SHA-256 of the verified file:
  `80db6203f81a2963033311b6bebc9616e2f05860b92cbaf67c698320f56b34da`;
- scope: new and reconstructed single-family residential houses,
  including houses with no more than ten autonomous blocks. Multi-apartment
  buildings are not included in this profile.

## What is encoded

Clause 7.8 requires natural lighting for living rooms and kitchens (dining rooms).
In `rules/kz_sn_3_02_02_2023_partial.yaml` this is represented by the deterministic
rule `DAYLIGHT_OPENING`:

- `living_room`, `bedroom` and `kitchen` are treated as the applicable room types;
- the presence of a derived exterior window opening is checked;
- the result contains a clause and evidence, so it can be verified by a human;
- `--require-provenance` requires the source details and the document hash to be present.

Clause 6.2.13 prohibits placing the bath-and-laundry block next to sleeping
rooms. It is represented by the rule `FORBIDDEN_TYPE_ADJACENCY`, which
checks for a shared rectangle edge between the types `bath_laundry_block` and
`bedroom`. If these types are not present in the plan, the result is
`NOT_APPLICABLE`, not a hidden PASS.

Clause 6.2.8 requires a vestibule (tambour) if an exterior entrance opens directly into a
heated room. In the model this is represented by an `external_entry` bound
to an exterior edge and the flag `RoomSpec.is_heated`. In the passing variant the entrance
leads into a room of type `vestibule`/`tambour`; in the failing variant, directly into a heated
hall. This is a check of the planning configuration, with no claim about the thermal
calculation of the vestibule.

Clause 6.2.12 requires that, where a veranda, terrace or loggia is provided, its
connection to the main rooms of the house be ensured. It is represented by the rule
`AUXILIARY_SPACE_ATTACHMENT`: the profile explicitly maps the types `veranda`, `terrace`,
`loggia` to `living_room`, `kitchen`, `bedroom` and checks for a shared boundary between
the rectangles. This is a project-level mapping of the term «основные помещения»
(English: "main rooms"), not a universal classification of all rooms.

Clause 8.19 requires that heating provide the normative microclimate in all
living rooms and other rooms with permanent occupancy. The current
model has no engineering network and no thermal calculation, so the rule
`HEATED_ROOM_COVERAGE` checks only the explicit flag `RoomSpec.is_heated` for
the types `living_room`, `bedroom` and `kitchen`. This is a declarative check of data
completeness, not a confirmation that the heating system works.

Mapping the norm's terms to room types is a design decision of the model, not
a claim that the profile already covers the entire normative document.

## What is not encoded yet

The profile is intentionally partial. `LayoutIR` does not yet have entities for fire
detectors, heating, engineering systems, structures or accessibility
requirements. Such clauses cannot be honestly implemented as rectangle checks;
they will be added in separate cycles after the model is extended and the norm
text is manually reviewed.

Therefore the current KZ ruleset is a check of five confirmed slices of the model,
not a building permit and not a full code check.
